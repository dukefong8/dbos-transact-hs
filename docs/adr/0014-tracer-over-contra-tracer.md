# Domain-event tracing over contra-tracer (amends ADR-0013's fast-logger removal)

Status: retired 2026-09-30 by ADR-0015, which replaced `DBOS.Logger` entirely.

New module `DBOS.Transact.Logger`: `Control.Tracer.Tracer` (`contra-tracer`, added to the cabal commons `build-depends`) as the single carrier for resource-lifetime events, with one backend per runtime. Production logs through FastLogger — re-added to `build-depends`, reversing ADR-0013's removal — as a Rank-N value (`fastLoggerTracer :: ToLogStr e => TimedFastLogger -> Tracer IO e`): one tracer serves every event type, each line carrying fast-logger's one-second-cached timestamp plus the event's own rendering. Simulations trace the structured event itself through io-sim's `traceM` (`simTracer :: Tracer (IOSim s) ResourceEvent`), recovered by type with `selectTraceEventsDynamic` instead of string matching.

Why fast-logger is back: ADR-0013 removed it because, with no message data type left, its only use was the timed sink and `Data.Time` covered that. The tracer design restores a real use — the Rank-N sink needs a backend that accepts *any* `ToLogStr` event, and fast-logger's `TimedFastLogger` plus one-second `newTimeCache` is exactly that, with buffering the `putStrLn` backend lacked. `ToLogStr` instances delegate to a small local contract (`LogEvent`: severity + line), so the builder vocabulary stays in one place.

Threading (explicit, per ADR-0012): the tracer rides the `Connection` (`connTracer`), which every `Ctx` inherits at `newCtx` (overridable with `withTracer`) and every dequeue worker reads directly — no signature churn in the workflow chain. The `Executor` carries the launch's tracer plus its release (`releaseTracer :: m ()`); `launch` acquires the backend, `shutdown` releases it after the tasks, a failed launch releases on the `Left` path. `DBOS.Transact.Logger` imports no `co-log`: severity is the event's own tag.

What stayed here, and did not: `DBOS.Logger` (co-log) was left untouched by this ADR to serve every unmigrated call site (`dbos_logger`, client/sysdb seams, workflow-attributed lines). ADR-0015 retired it too — co-log is now fully gone, migration was per-module and finished. Migration was per-module, not big-bang: `Step` run/replay announcements and the six dequeue/supervisor functions moved first; their rendered bodies stayed byte-identical, only the severity tag source changed. Recorded 2026-09-29.
