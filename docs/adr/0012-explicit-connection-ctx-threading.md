# Explicit Connection/Ctx threading replaces the Bluefin seam (supersedes 0006, amends 0008 and 0009)

The engine is now plain Haskell end to end. `WorkflowM` and every Bluefin import are deleted: a workflow body is `argument -> Ctx IO -> IO result`, the engine's internal runners take `Connection IO -> Identity -> Snapshot`, and every `SystemDB` method takes its backend as an explicit first argument (`class Monad m => SystemDB db m`). Nothing threads a carrier behind the caller's back — `DBOS`, `Ctx`, and `db` are parameters at each call site, matching Rust's `Ctx`/`Executor`/`Connection` ownership shape one-to-one instead of encoding it as a scoped capability. Bluefin was the wrong mechanism for this seam: Rust's `Ctx` is a clonable, explicitly threaded value with no lexical scope of its own, and expressing it as rank-2 handles forced a second carrier (`WorkflowM`) whose lifetimes did not correspond to any Rust lifetime, while every behavior the layer protected is already available from `io-classes` (`MonadFork`, `MonadMask`, `MonadSTM`, `MonadTime`, `MonadDelay`) with `IOSim` support that Bluefin cannot give.

The seam that replaces it, ported from `connection.rs`/`instance.rs`/`context.rs`: `Connection m {connSysdb :: SomeSystemDB m, connSerializer, connAppName, connOutcomePollInterval, connOwner}` where `Owner = OwnerApplication | OwnerClient` (constructor prefixes are the collision deviation style); `SomeSystemDB m` is a `forall db. SystemDB db m => db` existential so a `Connection` stays single-typed while the backend stays swappable, with `runSystemDB` to unwrap it and a stub instance for tests; `Executor m {conn, identity, workflows, listen_queues, tasks}`; `Ctx m {ctxConn, ctxIdentity, ctxWorkflow, ctxStep}` with `WorkflowState m` holding the workflow id, deadline, the `StrictTVar` step/marker counters, and the execution identity. `Tasks m` (`spawnTracked`/`abortAll`) gives structured concurrency over `MonadFork`/`MonadMask`/`MonadSTM` so the engine runs under `IOSim` as well as `IO`. The facade pins `IO` (`DBOS` holds `MVar (Maybe (Executor IO))`); polymorphism is the library's, not the app's.

Recorded deviations, each forced by a module cycle or by `IOSim`'s capabilities: `Ctx` carries a resolved `Connection` and `Identity` rather than an `Executor`, because `context.rs` and `instance.rs` are mutually dependent and Haskell modules cannot cycle; `forClient` lives in `DBOS.Transact.Client` because `Connection` cannot import `ClientConfig`; `StepMarker = StepMarker Int` comes from a per-workflow counter rather than `Data.Unique`, since `IOSim` has no `MonadIO` and markers only need per-workflow identity, which every comparison also checks. `DBOS.Transact` no longer exports `BackendErrorKind (..)`: its `Connection` constructor collides with `Connection`'s, so the kind is reachable through `DBOS.SystemDB` only.

Consequences: ADR-0006's two-layer Bluefin rule is retired (its plain-Haskell-internals half survives as the whole design); ADR-0009's "concrete forever" engine claim is retired — the engine is polymorphic in `m` and production pins `IO` at the facade; ADR-0008's io-classes rule extends from the retry loop to the whole engine, and `MonadIO` is banned in library code because `IOSim` does not have it. Recorded 2026-09-25.
