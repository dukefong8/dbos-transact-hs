# Postgres backend port deviations (polling-only, fixed schema, verify-only connect)

The `postgres.rs` rewrite (Phase 7) ports behaviour, not mechanism, in four places: LISTEN/NOTIFY is skipped entirely (`listener.rs`, `notifier.rs`, `notify.rs` — the oracle itself documents them as non-load-bearing, and polling every second is semantically identical), so waits use the short interval and `Config.useListenNotify`/`Settings.notificationCoalesce` are unsupported; SQL is `[typedSql|]` with identifiers pinned to the `dbos` schema (ADR-0007 discipline survives), so `Settings.schema` must equal `"dbos"` and the `Tables` struct has no counterpart; `connect` verifies the migration ceiling (108) instead of migrating (`Config.migrate` unsupported, ADR-0004 stands; `CREATE DATABASE` is also skipped); and wait loops are shared free helpers over instance-private typedSql fetches rather than per-instance loops, so `IOSimSystemDB` shares timing logic instead of duplicating it.

Amended 2026-09-24 (before P7.6): `notify.rs` and `postgres/notifier.rs` are now ported as `DBOS.SystemDB.Notify` and `DBOS.SystemDB.Postgres.Notifier`. The registry is what the waits subscribe to before their first look, and a wakeup only ever cuts a wait's polling interval short (`notified` races the interval); the notifier queues one payload set per channel and pushes it with a single `pg_notify` per channel per coalescing window, so `Settings.notificationCoalesce` is restored. Two halves of the original deviation stand: `listener.rs` is not ported — the receive side remains polling-only, so `Config.useListenNotify` still has no counterpart — and the notifier's flush loop is not spawned yet; the engine enables and runs it in P7.6, and until then `signal` only wakes local waiters while `pushing` stays off so nothing queues and nothing leaks. `Subscription` deregisters through an explicit `unsubscribe` (Rust's `Drop` has no Haskell hook).
