# Constrain impure internals with io-classes so the same code runs under IO and IOSim

Impure functions in the plain-Haskell internals — first `DBOS.SystemDB.Retry`'s retry loop, ported from Rust `sysdb::retry` — constrain their effects with `io-classes` classes (`MonadDelay`'s `threadDelay`), with the entropy word, the logger (`LogAction m Text`) and the retried action as explicit parameters, so one implementation runs under `IO` in production and under `IOSim` in tests, where time is virtual and entropy fixed; pure decisions (`shouldRetry`, `jitter`) stay pure functions and per-domain `Either` errors are unchanged. `io-classes` is not Bluefin, so ADR 0006's two-layer rule still holds — Bluefin stays at the external seam — and the previously unused `io-classes`/`io-sim` dependencies (main plus the `strict-stm`, `strict-mvar`, `si-timers` and `mtl` sublibraries) become real. `io-classes` has no randomness class, so jitter's entropy is an injected `m Word32` (a v4 UUID word in production) rather than a hidden source, which is what lets the jitter test be exact; tests assert retry timing with `runSim` and read retry warnings from the `say` trace instead of sleeping on real clocks.

Amended 2026-09-24 (Phase 7): the class carries `io-classes` constraints per method where callers must see them (`MonadDelay`/`MonadTime` on the waits), and the `ReaderT` instances come from the `io-classes:mtl` sublibrary (verified: `MonadAsync`, `MonadSTM`, `MonadMVar`, `MonadMask`, `MonadTimer`, `MonadTime` all lift through `ReaderT`). `MonadMask` implies `MonadThrow`, which Rule 3 still forbids for the *domain error channel*: `MonadThrow` here is for resource bracketing and `AsyncCancelled` only, which are rethrown at the edges without recording, while every DBOS error stays `Either Error`. `timestampNow` generalizes from `IO` to `MonadTime m => m Timestamp` so the same backend code reads real time under `IO` and virtual time under `IOSim`.

Amended 2026-09-25 (ADR-0012): the io-classes rule now covers the whole engine, not just `DBOS.SystemDB.Retry` — `MonadFork`/`MonadMask`/`MonadSTM` carry `Tasks` (`spawnTracked`/`abortAll`), `MonadTime`/`MonadSTM` carry `Ctx`'s counters and deadlines, and `MonadDelay`/`MonadTime` carry waits. `MonadIO` is banned in library code: `IOSim` has no instance, which is why execution identities and step markers avoid `Data.Unique` and use `StrictTVar` counters instead.
