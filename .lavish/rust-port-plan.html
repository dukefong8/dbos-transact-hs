6 · Rust → Haskell translation notes (reviewer request)

Grounded in context.rs:19–52 (task-local Ctx), workflow.rs:42–109,170–177,549–657 (Tasks, spawn_tracked 'static bound, borrowed option structs), step.rs:292–335 + event.rs:56–136 (PendingStep<'a> borrows), sysdb/mod.rs:91–92 (SystemDatabase trait), sysdb/postgres.rs:2582–2583 (its single impl), error.rs:1–85 (Error<E> channel), Bluefin README + Bluefin module docs (value capabilities, rank-2 handlers).

Rule 1 · Rust impl → Haskell module, not typeclass

  • Inherent impls (impl Connection/DBOS/Client/Tasks/Ctx) are namespaced functions — a Haskell module is exactly that. No class.
  • trait SystemDatabase + its single Postgres impl → concrete DBOS.SystemDB module with plain functions. One backend in scope (Python-schema compatibility is the boundary), so a class would be a hypothetical seam: interface without leverage.
  • If tests ever need a fake DB, reach for a record-of-functions (first-class, varies per test, works under io-sim), not a typeclass (instances are global and fight per-test variation).
  • #[async_trait] vanishes: IO needs no boxing; only the io-sim-covered parts abstract — today that is MonadDelay in DBOS.SystemDB.Retry (ADR-0008, revised 2026-09-23), while the queue/executor path stays plain IO+async/STM.

Rule 1b · Error channel → per-domain ADTs (built, unified DbosError deferred)

  • Error<E> became one ADT per domain — CodecError, StepError, WorkflowRunError, decode errors — instead of the predicted unified DbosError e. The generic parameter bought nothing with one backend and total functions; revisit if a second error producer needs combining.
  • trait DurableError (blanket over Serialize + Deserialize + Error) → constraints at use sites: (ToJSON e, FromJSON e, Exception e). No class declaration needed.
  • Rust enums with payloads (Outcome, step records) → Haskell ADTs directly — already the pattern in OperationCheckpointTypes.hs. #[non_exhaustive] → hide constructors or document the wildcard arm.

Rule 2a · Ambient context → explicit arguments (built, no WorkflowCtx record)

  • tokio::task_local! CURRENT: Ctx vanished entirely: bodies take (Pool, WorkflowId, input) explicitly. No ambient state, no ReaderT, no context accessors — there was never a second caller needing them.
  • Step ids are caller-passed OperationIds (matching the settled step-id-at-build shape #38/#43/#49); no shared step counter exists. The step-leaf rule is structural: steps take plain IO bodies, never nested runners.

Rule 2b · Resource scopes → supervised async (built on plain async/STM)

  • Per-attempt CancellationToken → fresh Async handle + cancel from the async package. Same rule as Rust: mint per attempt, never share across retries.
  • Tasks abort-set → Executor holding TVar [Async] + closed flag; post-close arrivals cancelled on arrival; shutdown cancels all and waits. Rows stay PENDING so a later executor recovers — preserved and tested.
  • Dequeue supervisor → superviseForever rounds on plain IO with short sleeps. The predicted MonadTimer determinism was not needed for the queue loop — live-DB tests with tight deadlines cover it. Revised 2026-09-23: io-classes/io-sim are no longer unused deps — adopted for the retry loop (ADR-0008), not for this one.

Rule 3 · Either in the core, base async exceptions at the edges (built)

  • Domain/durable failures (not-found, cancelled, decode conflict, replay mismatch, recorded step error) → explicit per-domain Either returns, mirroring Rust Result<T, Error<E>> (error.rs). Errors are data here: they are inspected for replay decisions and written into columns — exceptions would hide that control flow.
  • Cancellation (AsyncCancelled/ThreadKilled) is rethrown without recording — the shutdown test proves rows stay PENDING; body failures become ERROR outcomes. No MonadThrow/MonadCatch abstraction: the retry policy ported in Phase 6b retries on Either verdicts (shouldRetry), never on exceptions, and takes io-classes only for the wait (MonadDelay, ADR-0008).

Rule 4 · Bluefin seams in two layers (retired 2026-09-25, ADR-0012)

  • Where Rust uses lifetimes for scope: PendingStep<'a> borrows step names/keys (step.rs:292, event.rs:56); InitWorkflowCaller<'_> borrows the parent frame; NewWorkflow<'a>/Enqueue<'a>/StartOptions<'a> borrow user strings — converted to owned (OwnedEnqueue) before spawning, because spawn_tracked demands F: Future + 'static. Haskell needs no translation for the borrows: use owned Text everywhere.
  • Internal layer — plain Haskell, no Bluefin imports: DBOS.SystemDB typedSql IO fns, DBOS.Workflow core over an explicit WorkflowCtx record, Either DbosError returns, MonadAsync/MonadSTM constraints for io-sim. All logic and all tests (io-sim + live PG) live here.
  • External layer — Bluefin capabilities, no logic: thin Ask handles with rank-2 withX handlers over the internal functions (the existing withWorkflowExecutionStore shape). This is where callers get lifetime-like escape prevention; a capability cannot leave its handler. Dependency rule: Bluefin may depend on internal, never the reverse — deleting the outer layer loses scope safety but no behavior.
  • Dated revision 2026-09-25 (ADR-0012): the outer Bluefin layer was deleted and WorkflowM with it; Connection/Ctx are threaded explicitly (argument -> Ctx IO -> IO result, backend first in every SystemDB method). The internal-layer description above still holds and is now the whole design.

Rule 5 · Tracing: explicit SomeTracer, runTracer only, stderr routing (built; supersedes the LogAction card below)

  • One universal carrier (SomeTracer GADT over contra-tracer's Rank-N shape), never ambient; emission only through runTracer (projectTracer deleted, zero uses). Per-domain event ADTs homed with their owners (EngineEvent in Recovery, SysdbEvent in Retry, WorkflowEvent in Step, QueueEvent in Dequeue, ManagementEvent in Management, WaitEvent in Wait, SleepEvent in Sleep) with LogEvent+ToLogStr; showText in the Prelude. co-log is fully out (ADR-0015).
  • FastLogger Rank-N backend on IO writes stderr (stdout carries results); traceM on IOSim with typed asserts. Sim tracing is test-owned (test/DBOS/IOSimTracer.hs: simTracer/simTracerSay, runSimCase, printSimTrace to pane stderr so ghcid.txt holds results only); the sim backend lives in test/ with per-domain mock data, src keeps one backend-agnostic launchOn (ADR-0017).
  • Superseded history kept: the original card specified explicit LogAction m DbosLogMsg over co-log-core + fast-logger (stdout) with a say instantiation under sim — built through Phase 6b, then replaced per above.

Rule 6 · io-classes constraints for impure internals (ADR-0008, built)

  • Impure internals that need time constrain on MonadDelay (io-classes), never on IO directly — one implementation, two runners: IO in production, IOSim in tests where time is virtual and the run is instant. First module: DBOS.SystemDB.Retry.
  • Effects with no io-classes class are injected as parameters, never hidden: jitter's entropy is m Word32 (a v4 UUID word in production, pure 0 or a counter in sim) — there is no randomness class to reach for, and injection is what keeps jitter pure and its test exact.
  • Dated revision 2026-09-25 (ADR-0012): Bluefin is gone, so io-classes carries the whole engine — MonadFork/MonadMask for Tasks, MonadTime/MonadSTM for Ctx counters and deadlines, MonadDelay for waits. MonadIO is banned in library code (IOSim has no instance), and Rule 3 still rules out a MonadThrow/MonadCatch adoption.
  • Dependencies are real now: io-classes main plus strict-stm/strict-mvar/si-timers/mtl sublibraries; the audit of what each actually provides is docs/io-classes-sublibraries.md.

Rule 7 · Ported data modules keep Rust names and hide behind the facade (built)

  • Rust identifiers survive verbatim: BackendError, backendKind, ConflictingWorkflow, newQueue — no SystemDb prefix, no renaming for taste. DuplicateRecordFields went into cabal defaults so two records may share a field name (streamValue) exactly as Rust does; NoFieldSelectors + record-dot still govern access.
  • Domain modules are other-modules re-exported through the DBOS.SystemDB facade; tests import the facade, never the hidden module directly (a hidden-module import passes in a local ghci load and breaks cabal test).
  • A module imports its siblings plus external packages only: DBOS.SystemDB.Retry takes Types/Errors and Colog, not DBOS.Logger (2026-09-29: moved from DBOS.Transact.Logger) — which is why the log seam there is LogAction m Text rather than the structured message type.
  • Namespace collisions the oracle cannot have are resolved minimally and visibly: a prefix only where the bare name is taken (ForkStep beside WrittenBy.Step), never a wholesale rename.

Rule 8 · Test parity with the oracle, red-first, one watcher group (built)

  • Port the oracle's tests 1:1 where they exist (retry.rs: transient-retried / permanent-at-once / semantic-not-retried / opt-out / jitter-band → RetryTest), and record where they do not: error.rs has zero tests, so ErrorTest is a documented Haskell-only superset (18 Display render cases, including the RegisteredByAnother remedy text).
  • Red first, watched in ghcid.txt: per-group filtered runs (tasty DBOS.SystemDB.RetryTest.tests) are the inner loop; a group's signature fixtures (52/18/8) are names in the plan, not guesses.
  • test/Main.hs carries a -- $> / --- $> toggle with exactly one group enabled per ghciwatch reload, so watcher evals never overlap the live-DB suite; the full run is cabal test when the watcher is idle.

Rule 9 · Scoped capabilities + records (decided 2026-10-03, executing on proto/phantom-brands)

  • Complexity flows inward so the outside stays naive — the inverse of the TS/Rust SDKs (ambient state, closure capture, rules-as-documentation). Constraint-density belongs at the boundary (DBOS.Transact facade); mechanism (depth counter, journals, STM-everything) stays unnamed inside; capabilities flow down only (Executor → WorkflowCtx → StepCtx, tables → helpers → step bodies).
  • Enforcement ledger, per shape: compile-time where types reach (no step refs, JSON bounds, scope split, StepCtx-keyed op fields, cross-stack record separation); runtime refusal with matchable ADTs where capture defeats types (InsideStep via the shared depth counter, before any write/counter move); discipline where Haskell cannot reach (workflow determinism, raw pool — documented, skill-mapped).
  • Records over classes and over ambient handles: per-workflow step tables (first-class — two handlers coexist in one process), StepCtx-keyed invocation, registration-by-closure + explicit helper params + capture in bodies. Engine core stays ops-free; the IOSim instantiation is the proof (no MonadIO under sim).
  • Probes before tree: proto/deterministic-steps (Ops carrier + replay, 12/12) and proto/dual-store (Postgres-txn vs STM step table, 7/7 byte-identical invariants) validate each mechanism standalone; deltas fold back here per the loop.
