What the tables prove

  • The shared spine (launch, register, run, handles, events, messages, queues, sleeps) is present on both sides; of the 45 shape rows, 38 are Rust parity — the HS shape follows the Rust v0.5 oracle, so the divergence is TS ↔ Rust, not a port deviation. Only 7 differ from both: explicit contexts (Rust is task-local), the wait helpers, the ADR-0021 datasource/transaction seam, the debouncer, and the logging seam.
  • Every TS-only surface splits into two causes: oracle boundary (Rust v0.5 public API also lacks it — streams, schedules, patching, rewind, priority, auth context, class workflows, telemetry) and port gap — the one port gap (listWorkflowSteps) was closed by the 2026-10-07 TDD slice.
  • Skill references cover the whole shared surface; 6 TS references are absent and the skill's own navigation file is stale on one new reference (pattern-debouncing). Three "Difference from TS" sentences need wording fixes (details in Findings).

How to read

aligned same concept and close semantics · rust parity HS matches the Rust v0.5 oracle's shape — the divergence is TS ↔ Rust (explicit ctx/refs, typed errors, records) · shape deviation HS differs from both TS and Rust: the port's own design · Haskell-only no TS counterpart (Rust-shaped) · TS-only gap missing in the HS facade — the note names the cause: oracle (Rust v0.5 public API lacks it too) or port (Rust has it).

3 · Findings & follow-ups

Skill fixes (small, wording-level)

  1. Skill navigation stale. .agents/skills/dbos-transact-hs/AGENTS.md does not list pattern-debouncing.md under Pattern, and its "TS-only topics" list omits pattern-scheduled.md. Add both.
  2. workflow-background Δ is wrong. Replace "TS startWorkflow / DBOS.startChildWorkflow" with "TS DBOS.startWorkflow(fn, …) (children start the same way)".
  3. client-enqueue Δ is stale. TS 5.2 signature is client.enqueue(options: ClientEnqueueOptions, ...args); the named-args form is 4.x.
  4. pattern-sleep Δ is imprecise. TS exposes sleepms(ms), sleepSeconds(s), and sleep(ms) — not sleep(seconds).
  5. workflow-introspection Δ — resolved 2026-10-07. The reference now documents listWorkflowSteps / listWorkflowStepsInWorkflow / clientListWorkflowSteps.

Facade follow-ups (bigger, decide scope)

  1. Port gap — resolved 2026-10-07. listWorkflowSteps shipped on DBOS, in-workflow, and client entries (StepRecord (..) exported); oracle suite green, full suite 701 passed, psql mirror shows DBOS.listWorkflowSteps at step 1 of the self-listing case.
  2. Optional convenience parity — resolved 2026-10-07. Singular cancelWorkflow / resumeWorkflow (handle back) / deleteWorkflow / forkWorkflow (Nothing = from the top, Just point = forkFrom) and getWorkflowStatus shipped per the Rust singular surface; ForkPoint/ForkOptions/defaultForkOptions exported so fork callers can name the types. Full suite 702 passed; oracle suite green.
  3. TS-only by design (no action unless the port widens beyond Rust v0.5): streams, schedules, patching, rewind, workflow priority setter, auth context, scoped static helpers, class workflows, OTel/telemetry exporters, client renameApplication / transactional enqueue / debouncer-client.
  4. Queue option drift — you asked to port per TS. QueueOptions is a Rust-mapped ported type, so dropping priorityEnabled / reshaping pollingInterval into minPollingIntervalMs needs an ADR (HARD RULES: renames/splits need one). Disposition: ADR first, then the field change + skill/queue refs.
