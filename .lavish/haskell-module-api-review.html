DBOS Haskell review surface

Module structure and type-only API proposal

Purpose

This artifact maps the requested Python DBOS public concepts to a Haskell module structure and static typed API. It now distinguishes the committed Haskell surface from the remaining proposal backlog. The committed code exposes DBOS.Transact, DBOS.SystemDB, DBOS.SystemDB.Hasql, and DBOS.SystemDB.Queries; future runtime/context modules shown below are design proposals, not committed modules.

committed surface noted proposal backlog deep modules Bluefin scoped effects review by annotation

Review Rules

The page contains module names, public type declarations, and function signatures only. Sections labeled as proposals intentionally contain no implementation bodies and should not be read as current Cabal-exposed modules.

Committed public facade for Python-compatible system DB types and Hasql-backed operations.

public

DBOS.Transact.WorkflowExecution*

Committed internal workflow execution modules: status parser, row parser, and types.

internal

DBOS.Transact.OperationCheckpoint*

Committed internal operation checkpoint modules: parser, replay decisions, and result ADTs.

internal
Module structure rule: The committed public domain modules are DBOS.Transact and DBOS.SystemDB. Current internals live under DBOS.Transact.* and DBOS.SystemDB.Types; proposed .Capability, .Query, and .Adapter splits are future design options, not current code. DBOS-specific Handle records are not part of the Haskell API; effectful DBOS operations use Bluefin 0.7 capabilities.

Scoped Context Flow

Runtime

DBOSRuntime rt provides registry, system DB, queues, logger, serializer.

Workflow Scope

Workflow wf must exist before workflow-only operations compile.

Context Scopes

Auth, EnqueueOptionsContext, WorkflowTimeoutContext are introduced by with....

Operation Scope

OperationSlot wf op ties checkpoints to a workflow and operation name.

System DB

SystemDB db records and replays durable workflow facts.

Bluefin value-level capabilities replace Python's ambient context managers with scoped, typed evidence. A function that needs workflow context must accept the corresponding capability, so calls outside a workflow are rejected by the type surface rather than runtime checks.

Deep Module Review Points

Interface

The caller learns context capabilities and domain ADTs, not database columns or Python recovery internals.

small surface

Seam

The public seam is at DBOS.<FunctionalDomain>. Postgres and serializer adapters stay internal.

locality

Adapter

SystemDB and Datasource are concrete adapters. Add new adapters only when a second implementation exists.

no hypothetical seams

Illegal States

Workflow-only operations need Workflow wf. Checkpoint writes need OperationSlot wf op, tied to that workflow scope.

typed context

Compatibility

Python DBOS schema and status strings remain the external compatibility boundary.

do not migrate schema

Open Review

Annotate names, missing Python mirrors, or capability requirements that feel too strict or too loose.

feedback target
